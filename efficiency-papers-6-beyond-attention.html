01 // The Quadratic Problem

Every token attends to every other token. That single design decision — pairwise comparison across the full sequence — is both the fundamental promise of self-attention and the fundamental problem with it. At 1,000 tokens, the attention matrix contains one million entries. At 10,000, one hundred million. At 100,000, ten billion. Double the context, quadruple the cost. This is not a constant you can engineer away or a coefficient you can shrink. It is the exponent of the algorithm itself.

In Part I of this series, we watched Tri Dao attack this problem with FlashAttention — tiling the attention computation so it fits in fast SRAM, avoiding the catastrophic memory traffic of materializing the full N×N matrix in slow HBM. It worked brilliantly. FlashAttention gave a 2-4x wall-clock speedup with zero approximation. Every major framework adopted it. The attention tax got cheaper.

But the tax was still quadratic.

FlashAttention changed the constant, not the exponent. At 4K tokens, that constant matters enormously — it's the difference between a model that fits on one GPU and one that doesn't. At 256K tokens, no constant saves you. The quadratic curve bends upward and nothing you do to the constant factor prevents it from eventually dwarfing everything else. You need a different curve entirely.

What if, instead of comparing every token against every other token, you could process each token exactly once? Read it, update a fixed-size state, and move on. Never look back. O(n) instead of O(n²). No KV cache growing without bound. Constant memory per token during generation. The same cost to generate token 1,001 as token 1. The same memory at 256K context as at 4K.

That is the promise of state space models. For decades, they lived in control theory — modeling physical systems like aircraft dynamics, chemical reactions, and signal processing. In 2020, Albert Gu and colleagues at Stanford began asking: what if the same mathematical framework could model sequences of text? The answer would take four years, three major architectures, and one of the most surprising mathematical equivalences in modern machine learning to fully unfold.

Drag the slider. At 4K tokens, FlashAttention keeps attention competitive — you can see the orange dashed line tracking close to the green. At 16K, a factor-of-ten gap opens. At 64K, the gap is an order of magnitude. At 256K, attention costs over 3,000 times more compute than a linear-time model. The curves do not negotiate. Quadratic is quadratic.

Put it in dollar terms. If an SSM costs you $1 to process a 256K-token document, standard attention costs $3,000. FlashAttention brings that down to about $1,000. Still unacceptable. The exponent rules everything at scale.

And this is only the compute cost. The memory cost is worse. Attention requires a KV cache that grows linearly with sequence length — every token you process adds to the cache, and the cache must persist for the entire generation. At 256K tokens with a 70B model, the KV cache alone can exceed 100GB. That is an entire GPU's worth of memory consumed by just the cache, leaving nothing for the model weights, activations, or anything else. Batch size goes to 1. Throughput collapses.

An SSM's state is fixed-size regardless of sequence length. Process a thousand tokens or a million — the state vector stays the same size. A Mamba model with a 256-dimensional state uses the same memory at 1K tokens as at 256K tokens. The batch size stays constant. The throughput stays constant. The memory bill does not grow with the conversation.

The Exponent Wall

FlashAttention changed the constant on the quadratic curve. It did not — and cannot — change the exponent. For long-context inference, you do not need faster attention. You need to replace it.

The history of SSMs is the history of trying to build that replacement. It begins with a mathematical insight about memory, passes through a structural limitation that blocked progress for two years, and culminates in a revolution that merged the two fields into one. Along the way, it reveals that the replacement looks more like attention than anyone expected — and that attention, viewed correctly, was always a state space model in disguise.

02 // State Space Models

Imagine a reader summarizing a thousand-page book. After each page, they update a fixed-size notepad — maybe a hundred lines of notes. When asked a question about the book, they answer from the notepad, never from the book itself. The notepad is the hidden state. The update rules are the model parameters. The question is always: what did you choose to write down?

That is a state space model. It comes from control theory — the mathematics of systems that evolve over time. Two equations define it: 

SSM Core// State equation: how hidden state evolves
h'(t) = A · h(t) + B · x(t)

// Output equation: how state maps to output
y(t)  = C · h(t)

// A: state dynamics (N x N)  — how the notepad updates itself
// B: input projection (N x 1) — what enters the notepad from input
// C: output projection (1 x N) — what we read from the notepad

The state h(t) is a vector — think of it as a compressed summary of everything the model has seen so far. Matrix A controls how the state evolves on its own: the decay, the memory, the internal dynamics. If A is zero, the state has no memory — each output depends only on the current input. If A is identity, the state remembers everything forever — but also accumulates noise without bound. The art of SSM design is choosing A so the state remembers what matters and forgets what doesn't. Matrix B controls how new input gets written into the state. Matrix C controls what gets read out.

Notice what is absent: there is no mechanism for the state at position 47 to directly access the input at position 12. The state at position 47 is a compressed function of ALL prior inputs, mediated through the recurrence. This is fundamentally different from attention, where position 47 can directly compute a similarity score with position 12 and retrieve its value. The SSM state is a summary. The attention KV cache is a database. This distinction drives every architectural choice in the rest of this article.

This is a continuous-time formulation. To handle discrete tokens — words, audio samples, DNA bases — you discretize: a learnable step size Delta converts the continuous dynamics into a step-by-step recurrence. Each token's value is "held" until the next token arrives, converting the discrete stream into a piecewise-constant signal, processing it, then sampling back.

The Dual Personality

Here is the beautiful trick. The same SSM can be computed two entirely different ways:

Recurrent Mode

Process tokens one at a time. Update state sequentially. O(1) per step, constant memory. Perfect for inference — generate one token, update state, generate the next. But impossible to parallelize during training.

Convolutional Mode

Unroll the recurrence into a single convolution with a kernel derived from A, B, C. O(n log n) parallel. Perfect for training — process the entire sequence at once on GPU. But requires a fixed kernel.

Same math. Two algorithms. One for training, one for inference. This duality is extraordinary — no other sequence model has it. RNNs are recurrent but have no convolutional form. CNNs are convolutional but have no recurrent form. Transformers are neither. SSMs are both.

Pre-Mamba SSMs used both: convolutional mode for the forward pass during training (where you need to process the entire sequence in parallel), recurrent mode for autoregressive generation (where you process one token at a time). Best of both worlds — if your parameters never need to change per-token.

Now the comparison with attention becomes crisp. A Transformer keeps the entire book open on the desk. It can flip to any page instantly — the KV cache is an explicit database of every token the model has seen. Ask about something from chapter 3? The model looks it up directly. Powerful, but the book gets bigger with every word, and eventually it fills the desk, then the room, then the building. An SSM only has the notepad. Compact and fast — the notepad stays the same size whether the book is 100 pages or 100,000. But it can only answer from what it chose to write down. If it did not record a fact, that fact is gone.

Discretization: From Continuous to Tokens

The raw SSM equations are continuous-time — the state flows smoothly, not in discrete steps. But language is discrete. Audio is sampled. DNA comes in base pairs. To handle tokens, you discretize the continuous dynamics using a zero-order hold and a learnable step size Delta.

The discretization converts the continuous matrices into their discrete equivalents: 

Discretization// Zero-Order Hold: convert continuous (A, B) to discrete (A_bar, B_bar)
A_bar = exp(Delta · A)         // matrix exponential
B_bar = (A_bar - I) · A^-1 · B  // scaled input matrix

// Now the recurrence is discrete:
h[t] = A_bar · h[t-1] + B_bar · x[t]
y[t] = C · h[t]

Think of Delta as a zoom lens. Large Delta = wide aperture, the model integrates more of the input into the state per step. Small Delta = narrow aperture, the model takes finer-grained steps and the state evolves slowly. In pre-Mamba SSMs, Delta is a fixed hyperparameter — every token gets the same aperture. In Mamba, as we will see, Delta becomes input-dependent: the model adjusts the lens for every token. That one change — from fixed to learned Delta — is arguably the most consequential idea in the entire SSM lineage.

The Core Trade

Attention is a database — stores everything, retrieves anything, grows without bound. An SSM is a brain — compresses everything into finite state, processes in constant memory, but the compression is lossy. The question of this entire article: when is the brain enough?

03 // The Mechanical Clock

In 2020, Albert Gu at Stanford asked a question that would reshape sequence modeling: what should matrix A look like? If A is randomly initialized, the SSM behaves like a leaky bucket — recent inputs are vivid, but information from 50 tokens ago has evaporated into noise. This is the same vanishing gradient problem that killed vanilla RNNs in the 1990s, wearing a different hat.

Gu's answer was HiPPO (High-order Polynomial Projection Operators, NeurIPS 2020): instead of random values, construct A so the hidden state tracks Legendre polynomial coefficients of the entire input history. This is not a learning trick or a training heuristic. It is a mathematical structure derived from approximation theory.

HiPPO defines A so that, at every timestep, the hidden state is the optimal polynomial approximation of all input seen so far under a specific measure. Each dimension of the hidden state corresponds to a coefficient of the Legendre polynomial expansion. Dimension 0 tracks the running mean. Dimension 1 tracks the first-order trend. Dimension 2 tracks curvature. Higher dimensions capture progressively finer detail. Recent tokens are captured precisely because all coefficients are fresh. Older tokens decay gracefully — not exponentially to zero, but as a smooth polynomial rolloff that preserves the gist even when details fade. The high-frequency coefficients decay first (fine details lost), while low-frequency coefficients persist (broad structure retained). The notepad becomes an optimal compressor.

Two years later, Gu combined HiPPO with two more ingredients. First, a structured parameterization: S4 conditions matrix A with a low-rank correction that enables stable diagonalization. A naive diagonalization of the HiPPO matrix is numerically unstable; S4's structured approach avoids this. Second, an efficient computation trick: by reducing the SSM computation to a Cauchy kernel — a well-studied mathematical object with existing fast algorithms — S4 achieved O(n log n) training instead of the O(n²) that a naive approach would require.

The result was S4 — Structured State Spaces for Sequences — published at ICLR 2022, where it received an Outstanding Paper Honorable Mention. The results were extraordinary.

The Long Range Arena (LRA) benchmark was designed to test architectures on extreme-length sequences. Every Transformer variant had plateaued below 60% average accuracy. S4 scored 80.48%. On Path-X — a sequence classification task at 16,384 tokens — every prior architecture performed at chance. Random guessing. S4 solved it.

For the first time, a non-attention architecture dominated on the tasks that were supposed to prove attention's superiority.

What S4 Proved

The results bear repeating. On Long Range Arena, the benchmark specifically designed to test long-sequence architectures, every Transformer variant — vanilla, Performer, Linear Transformer, Reformer — scored below 60% average. S4 scored 80.48%. On Path-X, a task requiring the model to track a path through a 128x128 image flattened into 16,384 tokens, Transformers literally performed at random (50% on a binary classification). S4 cracked it.

This was not incremental. This was a regime change. For context: LRA had been considered intractable for Transformers for years. Efficient Transformer variants (Performer, Linear Transformer, BigBird) had chipped away at it without breaking through. S4 obliterated the benchmark with an entirely different paradigm — no attention mechanism anywhere in the model. The HiPPO initialization gave S4 a mathematically principled long-range memory that no amount of positional encoding could match.

What made S4's long-range performance possible was HiPPO's polynomial compression. Where a randomly-initialized SSM loses signal exponentially — tokens at distance D are attenuated by roughly e^(-D) — HiPPO maintains a polynomial approximation that decays gracefully. At distance 1000, a random SSM has lost everything. A HiPPO-initialized SSM retains the gist. The difference is structural, not learned: it is baked into the eigenvalue spectrum of matrix A.

The Fatal Flaw

Then researchers tried S4 on language modeling. It failed.

Not failed-somewhat. Failed structurally. S4 could not do in-context learning. Could not learn from few-shot examples in the prompt. Could not solve selective copying — given [a, noise, b, noise, c, MARKER], copy out [a, b, c]. Could not form induction heads — detect the pattern "A B ... A" and predict "B."

The reason is elegant and damning. S4's matrices A, B, and C are fixed per layer. They do not change based on what the input is. Every token passes through identical dynamics. The model is a mechanical clock: perfect rhythm, exquisite engineering, but no judgment. 

The LTI Constraint// S4: parameters are FIXED (Linear Time-Invariant)
for token in sequence:
    h = A · h + B · token   // same A, same B, every time
    y = C · h                 // same C, no matter what token is

// "quantum" gets the same processing as "the"
// a keyword gets the same weight as filler
// the clock ticks at the same rate regardless of content

This is Linear Time Invariance (LTI). It means S4 literally cannot implement if token == important: pay_attention(). The math forbids it. The model treats every input identically — brilliant for audio waveforms where every sample matters roughly equally, catastrophic for language where information density varies wildly from token to token.

Consider a concrete example. The sentence: "The capital of France, which has been the subject of many discussions in recent parliamentary sessions involving various stakeholders from across the European Union, is Paris." A human reader skims the subordinate clause and lands hard on "Paris." An attention mechanism can do the same — the attention score for "Paris" given the query "capital of France" will be high, regardless of the filler in between. An LTI SSM processes every word in that subordinate clause with the same dynamics as "Paris." By the time it reaches the answer, the state has been polluted by 20 tokens of noise, each written with equal strength.

Apple's ML research team confirmed this in a targeted study: state spaces alone are not enough for machine translation. The tasks that require content-aware gating — aligning source and target words, handling reordering, tracking agreement across clauses — break on LTI dynamics. Language is not like audio. It is not like control signals. It has variable information density, long-range dependencies that are content-specific, and syntax that requires selective memory. The mechanical clock cannot parse a sentence because parsing requires knowing which words are verbs, which are nouns, and which are filler — and treating them differently.

The Mechanical Clock Problem

S4 solved the memory problem (HiPPO tells you HOW to remember) but not the selection problem (WHAT to remember). Language requires both. Fixed parameters give you a perfect stenographer who transcribes everything at constant speed but cannot skim, skip, or focus. When the CEO says "this next part is critical," the stenographer does not change behavior.

S4 proved that linear-time models could capture long-range dependencies Transformers couldn't. But it also proved something harder: memory without selection is not enough. The model needs to decide, per token, what matters.

The Convolutional Mode Explained

Why can S4 use convolution? Because its parameters are fixed, you can unroll the recurrence algebraically. The output at position t depends on all prior inputs weighted by powers of A:

y[t] = C · A_bar^t · B_bar · x[0]
     + C · A_bar^(t-1) · B_bar · x[1]
     + ...
     + C · B_bar · x[t]

// This is a convolution with kernel K:
K = [CB_bar, CA_barB_bar, CA_bar^2B_bar, ...]
y = K * x   // convolution, computable via FFT in O(n log n)

The kernel K is precomputed once per layer. This is why fixed parameters enable O(n log n) training. The moment you make B or C input-dependent, K changes at every position and the convolution disappears.

The question hung in the air for eighteen months: can you make SSM parameters input-dependent without losing the efficiency that makes SSMs worth building?

04 // The Selective Revolution

In December 2023, Albert Gu and Tri Dao published a paper that answered the question with elegant brutality. They called it Mamba: Linear-Time Sequence Modeling with Selective State Spaces. The fix was disarmingly simple: make B, C, and Delta functions of the input.

Not functions of the layer. Not functions of the position. Functions of the actual token being processed right now. Each input passes through a small linear projection to produce its own B, its own C, its own Delta. Three projections, each a single matrix multiply. The overhead is trivial. The impact is fundamental. The mechanical clock gains a conductor who can speed up, slow down, amplify, or ignore — all in response to what the music demands. 

Mamba: Input-Dependent Parameters// Mamba: parameters respond to content
for token in sequence:
    B_t = project_B(token)     // what enters the state (content-aware)
    C_t = project_C(token)     // what we read out (content-aware)
    Delta_t = softplus(project_Delta(token))
                                // how much to remember vs forget
    A_bar = exp(Delta_t · A)  // A stays fixed — stable dynamics
    B_bar = Delta_t · B_t

    h = A_bar · h + B_bar · token
    y = C_t · h

Delta is the key. It controls the resolution of discretization — how strongly the model integrates the current input versus coasting on the existing state. Large Delta means "this token matters, write it hard into the state." Small Delta means "this is noise, let the state barely change." Delta is the attention gate of the SSM world — the same per-token importance scoring that attention provides, achieved through a completely different mechanism.

Matrix A stays fixed. Its job is stable base dynamics — decay rates inherited from HiPPO. Making A input-dependent would add complexity without proportional benefit, because A's role is providing the background memory structure, not per-token gating. The selectivity comes from the gates around it: B decides what enters, C decides what gets read, Delta decides how strongly. The clock gains a conductor.

Note the analogy with attention. In a Transformer, the attention scores determine per-token importance: "How much should position 47 attend to position 12?" In Mamba, Delta performs the same function through a completely different mechanism: "How strongly should position 47 write into the state?" High attention score and high Delta achieve the same effect — amplifying the signal from an important token — through architectures that share no components.

The selective model's state has structure — peaks where information-rich tokens arrived, valleys where filler passed through. The state has become a content-aware summary, not a mechanical average.

The Price of Selection

Making parameters input-dependent kills the convolutional representation. Convolution mode works because you can precompute a fixed kernel from A, B, C. If B and C change at every timestep, there is no fixed kernel. The elegant O(n log n) parallel training disappears.

So Mamba abandons convolution entirely and runs purely in recurrent mode. This is the painful sacrifice. The elegant dual-mode computation that made S4 attractive — convolutional for training, recurrent for inference — disappears. Selection and convolution are mutually exclusive. You can have content awareness or parallel training via convolution, but not both.

But recurrence is sequential — process token 1 before token 2 before token 3. How do you parallelize training on GPUs that thrive on parallelism?

This is where Tri Dao's FlashAttention expertise becomes decisive. The answer is a parallel associative scan. The SSM recurrence h_t = A_t * h_{t-1} + B_t * x_t can be rewritten as a binary operator that combines (state, input) pairs. The key observation: this operator is associative. Associativity means you can reorder computations without changing the result: instead of computing tokens 1, 2, 3, 4 sequentially, compute (1,2) and (3,4) in parallel, then combine. O(log L) parallel depth instead of O(L). This is a well-known technique from parallel computing — the prefix sum algorithm — applied to the SSM recurrence.

But the real trick is not the scan algorithm — it is the IO-aware kernel fusion. The naive implementation would materialize the full expanded state (batch x dim x length x state_dim) in GPU HBM. That tensor is enormous. Instead, Mamba loads SSM parameters directly from slow HBM to fast SRAM, performs discretization and the entire recurrence in SRAM, and writes only final outputs back. The expanded intermediate state never touches HBM.

The Tri Dao Connection

This is the same principle as FlashAttention. Exactly the same. FlashAttention tiles the attention matrix to fit in SRAM, never materializing the full N×N matrix in HBM. Mamba scans the SSM state in SRAM, never materializing the expanded state in HBM. Same author. Same insight. Different substrate.

The fused selective scan runs 40x faster than a naive implementation. For backpropagation, intermediate states are recomputed rather than stored — trading compute for memory, just like gradient checkpointing but at the kernel level. The bottleneck was never the algorithm. It was always memory movement.

The Parallel Scan: Associativity Enables Speed

The associative scan deserves a closer look, because it is the key that makes selective SSMs trainable. Consider a sequence of 8 tokens processed sequentially: 8 steps, one after another. The parallel scan exploits the fact that the SSM recurrence defines an associative binary operator — you can group operations arbitrarily.

Parallel Scan: 8 Tokens in 3 Steps 

  Sequential: 8 steps
  h1 → h2 → h3 → h4 → h5 → h6 → h7 → h8

  Parallel scan: 3 steps (log2 of 8)
  Step 1: (h1,h2)  (h3,h4)  (h5,h6)  (h7,h8)   ← 4 pairs in parallel
  Step 2: (h1-2, h3-4)    (h5-6, h7-8)       ← 2 pairs in parallel
  Step 3: (h1-4, h5-8)                       ← 1 combine

  Same result. O(log L) depth instead of O(L).

The scan produces identical results to sequential processing — associativity guarantees this mathematically. The binary operator op(a, b) that combines two state transitions satisfies op(op(a, b), c) = op(a, op(b, c)), so you can group operations arbitrarily without changing the result. Because each level of the tree can be computed in parallel on GPU, the depth drops from L to log L. For a 4096-token sequence, that is 4096 sequential steps versus 12 parallel levels. For 64K tokens, 16 levels instead of 65,536 steps.

The scan alone is not enough, though. Without IO-awareness, you are just doing the wrong thing faster. The fused kernel is what makes it practical.

The Simplified Architecture

Mamba does not merely replace attention with a selective SSM. It simplifies the entire block. No separate attention module. No separate MLP. One block: expand, conv1d, selective SSM, gate (SiLU on a parallel branch), project down. The gating provides the nonlinearity that the missing MLP would have contributed. This is radically simpler than a Transformer block with its multi-head attention, two layer norms, MLP, and residual connections around both.

Results

At 3B parameters, Mamba matched or exceeded Transformer baselines of the same size on language modeling. It solved selective copying and induction heads — the exact tasks S4 failed at. It achieved state-of-the-art on audio and genomics. And it ran at 5x higher throughput than Transformers at inference, with linear scaling in sequence length.

The throughput number deserves emphasis. Five times faster does not mean 5% faster, or "marginally better on a cherry-picked benchmark." It means that for every token a Transformer generates, Mamba generates five. At inference prices measured in dollars per million tokens, this is the difference between profitable and unprofitable, between a product that scales and one that doesn't.

On genomics — where sequences routinely exceed 100K bases — Mamba established new state-of-the-art across multiple benchmarks. On audio, where each second contains 16,000 or more samples, the linear scaling made Mamba practical at durations where attention-based models could not even load the sequence into memory. Consider: 10 seconds of audio at 16KHz is 160,000 timesteps. The attention matrix alone would require 160,000 × 160,000 = 25.6 billion entries. Even in FP16, that is 48GB — more than most GPUs have. An SSM processes the same audio in linear time with a fixed-size state. The efficiency advantage is not theoretical. It is the difference between "can run this task" and "cannot."

The Revolution

Mamba proved three things simultaneously: SSMs can do language. Selection is the missing ingredient. And IO-awareness — the same principle that made FlashAttention fast — is universal. Whether your inner loop is a softmax or a scan, the optimization target is identical: minimize transfers between slow and fast memory.

The Mamba paper landed in December 2023 like a thunderbolt. Within weeks, open-source implementations appeared on GitHub. Within months, every major lab was experimenting with Mamba layers. The Hugging Face community built integrations. Research groups published Mamba variants for vision, graphs, point clouds, and protein folding. The architecture's simplicity — fewer components than a Transformer block, no positional encoding needed — made it easy to adapt.

But a question lingered: Mamba was good at language modeling. Was it good enough? The 3B results were impressive, but Transformers had seven years of scaling laws, battle-tested training recipes, and billions of dollars of infrastructure investment. Could SSMs compete at 70B? At 400B? Could they handle the full spectrum of tasks that modern LLMs are expected to perform — reasoning, coding, retrieval, instruction following?

The answer would come from an unexpected direction. Not by scaling Mamba to compete with Transformers head-on, but by combining the two into something neither could achieve alone.

05 // Duality and Beyond

Six months after Mamba rewrote the rules for efficient sequence modeling, Dao and Gu dropped a mathematical bombshell. The title of the May 2024 paper said it plainly: "Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality."

Read that title again. Not "SSMs are like attention." Not "SSMs approximate attention." Are. The State Space Duality (SSD) framework proves a mathematical equivalence that collapses the "SSM vs. attention" debate into a false dichotomy. A state-space model with a scalar-times-identity state matrix computes the same transformation as masked self-attention with a specific matrix structure — a 1-semiseparable causal mask. Same input, same output, two algorithms. The proof goes through structured matrices: the SSM's output has a specific low-rank structure below the diagonal that corresponds exactly to a particular attention mask pattern.

The connection runs through structured semiseparable matrices. When you unroll an SSM's recurrence, the input-to-output mapping can be expressed as a matrix multiplication y = M * x where M is lower-triangular (causal) and has a specific low-rank structure in each entry. This is exactly the structure of a 1-semiseparable matrix — and it corresponds to a particular attention mask pattern. When all the scalar A values equal 1 (no decay), the SSM collapses to standard causal linear attention. SSMs and attention are not rival architectures. They are endpoints on the same spectrum, connected by the decay parameter.

The SSM View

Linear-time O(T) recurrence. Process tokens sequentially, update state. Fast at inference, hard to parallelize.

The Attention View

Quadratic-time O(T²) matrix multiply. Process all tokens at once. Easy to parallelize, expensive at long sequences.

Same computation. Two decompositions. The question is not "which is correct?" but "which is faster on your hardware for your sequence length?" For short sequences, the matmul version is faster (GPUs are spectacularly optimized for matrix multiplication). For long sequences, the recurrence is faster (linear beats quadratic). The optimal strategy is both.

Drag the decay slider. When A approaches 1, both matrices become the standard causal mask — every token attends equally to all prior tokens. The triangle fills completely. This is the "no forgetting" regime: the SSM remembers everything, just like standard causal attention. When A is low, only the diagonal glows — each token sees only itself and its immediate neighbors. This is the "rapid forgetting" regime. At every position between, the SSM and attention matrices are identical. The duality is not an approximation. It is an algebraic identity.

The implications are profound. Every efficient attention variant (linear attention, local attention, sliding window attention) corresponds to a specific choice of A in the SSM framework. Every SSM with a specific decay structure corresponds to an attention pattern. Researchers who thought they were working on separate problems were solving the same problem from different ends. The unification simplifies the entire field: instead of a zoo of architectures, there is a single family parameterized by the decay structure, and the question is which member runs fastest on your hardware.

Mamba-2: The Practical Payoff

The duality was not merely theoretical. It unlocked a dramatically faster architecture. By restricting A to scalar-times-identity (all diagonal entries identical), Mamba-2 could use matrix multiplication as its core primitive instead of the custom CUDA scan kernels Mamba-1 required.

That last row is the clue. Mamba-2 uses a chunked algorithm: divide the sequence into chunks of, say, 256 tokens. Within each chunk, use the quadratic (attention-like) computation. Why? Because for 256 tokens, the 256×256 matrix multiply fits comfortably on Tensor Cores, and matmul is what GPUs do fastest. Between chunks, pass state using the linear (SSM) recurrence — a single state vector bridging the gap from one chunk to the next.

    state = ssm_recurrence(state, chunk)

// Quadratic LOCALLY (where it's fast), linear GLOBALLY (where it matters)

This hybrid algorithm is faster than either pure approach. Pure recurrence wastes GPU parallelism. Pure attention wastes memory and compute at long ranges. The chunked approach uses quadratic where it is cheap (short chunks) and linear where it is necessary (long sequences). The duality is not just a theorem. It is an engineering blueprint.

The implementation simplification is staggering. Mamba-1 required hundreds of lines of custom CUDA kernels — intricate, hardware-specific code that few researchers could modify or port. Debugging required deep GPU programming expertise. Mamba-2's core is approximately 30 lines of Python, using standard PyTorch operations. Any ML engineer can read it, modify it, and extend it.

This accessibility matters more than it might seem. In ML research, adoption speed determines impact. FlashAttention succeeded not just because it was fast, but because it was adopted everywhere — PyTorch, JAX, TensorRT, every major framework integrated it within months. Why? Because Dao worked with each framework's maintainers to ensure compatibility. Mamba-1's complex CUDA kernels were a barrier to the same kind of adoption — porting them to AMD GPUs or TPUs required reimplementing the entire kernel from scratch.

Mamba-2's simple matmul-based implementation removed that barrier entirely. Any platform that can do matrix multiplication (which is to say, every platform) can run Mamba-2. The duality turned a systems engineering problem into a linear algebra problem, and linear algebra has mature, optimized implementations on every chip ever manufactured for machine learning.

The Mamba-2 Chunked Algorithm in Detail

The SSD algorithm divides the sequence into chunks of size C (typically 64-256 tokens). Within each chunk:

Intra-chunk computation uses the quadratic (attention-like) form: compute a C×C matrix of token-to-token interactions and multiply by the value matrix. This leverages Tensor Cores, which are optimized for matrix multiplication. For chunk size 256, the 256×256 matrix is small enough that the quadratic cost is negligible.

Inter-chunk state passing uses the linear (SSM) form: the hidden state at the end of chunk k is passed to chunk k+1 via the SSM recurrence. This is a single matrix-vector multiply per chunk boundary — O(1) per transition.

The total cost: O(T · C) for intra-chunk (quadratic within chunks of size C, but there are T/C chunks) plus O(T/C · N) for inter-chunk state passing. By choosing C appropriately, this is faster than either pure O(T²) attention or pure O(T · N) scan.

Mamba-3: Complex Values and MIMO

At ICLR 2026, the latest evolution arrived with three innovations rooted in classical control theory.

Complex-valued state spaces. Mamba-3 models the SSM state as complex numbers. Complex transitions act as rotations in the state space, not just scalings. A real-valued state can stretch or shrink along the real axis. A complex-valued state can rotate — maintaining magnitude while shifting phase. This is mathematically equivalent to applying data-dependent Rotary Position Embeddings (RoPE) on the B and C projections. The implication is startling: Mamba-3 reuses the RoPE module already optimized in every Transformer library. No new kernel required. SSM researchers and Transformer researchers, working independently, converged on the same mathematical object.

The payoff is concrete. On the Parity task — a challenging state-tracking benchmark that requires the model to track cumulative XOR over a sequence — Mamba-2 achieves 0.9% accuracy. Essentially random. Mamba-3 achieves 100%. Complex values crack state tracking in a way real values cannot, because rotations preserve information that scaling destroys.

MIMO (Multi-Input Multi-Output). Previous Mamba versions used SISO dynamics — each channel processed independently, no cross-channel interaction within the SSM. MIMO couples multiple input and output channels, switching from an outer-product state update to a matrix-multiplication state update. Channels now interact within the state transition itself, not just in the projections around it. It improves downstream accuracy by 1.2 percentage points at 1.5B scale, and the MIMO state is 2x smaller than the equivalent SISO state for the same expressivity. A rare Pareto improvement: better and cheaper simultaneously.

Exponential-trapezoidal discretization. Mamba-3 also replaces the zero-order hold discretization of Mamba-1/2 with an exponential-trapezoidal method. Where zero-order hold assumes the input is constant between timesteps (a coarse approximation), the trapezoidal rule interpolates between the start and end of each step. The result: richer transition dynamics per step, meaning the recurrence can model more complex temporal patterns without increasing the state size. A small change in the discretization formula, but it allows each step to capture nuance that previously required multiple steps.

At 1.5B parameters, Mamba-3 beats Gated DeltaNet (the previous best non-attention model) by 1.8 points average. It achieves the fastest combined prefill + decode latency across all sequence lengths tested, beating Mamba-2, Gated DeltaNet, and optimized Transformers. The evolution from S4 to Mamba-3 spans just four years, but the distance is enormous: from a model that could not do language to one that beats Transformers at it.

Complex SSMs turn out to be equivalent to RoPE — a Transformer technique invented by Jianlin Su in 2021. MIMO uses matrix multiplication as its core primitive — the same hardware-friendly operation Mamba-2 pivoted to. Mamba-3 beats the previous best non-attention model by 1.8 points average at 1.5B scale. The boundary between "SSM technique" and "Transformer technique" has dissolved. These were never separate fields. They were always one field, seen from two angles, converging on the same mathematical objects.

06 // Hybrids Win

Pure Mamba has a structural ceiling: fixed-size state means lossy compression. A Transformer's KV cache is an explicit database. Every past token's key and value are stored and retrievable exactly. Ask "what was the 47th token?" and attention can look it up. Ask the same of an SSM and the answer is: it has been blended into a 256-dimensional state vector along with everything else. You cannot un-blend it.

This manifests in specific failure modes. Exact copying over long distances — "repeat this paragraph verbatim 2,000 tokens later" — Transformers handle trivially via the KV cache; SSMs degrade as distance grows. Phonebook lookup — given a name-number mapping seen once, retrieve the number for a specific name — requires exact storage, not compression. Complex in-context learning where the model must simultaneously track multiple independent facts and retrieve specific ones on demand.

A Harvard study formalized this rigorously: Transformers are provably better than SSMs at copying tasks. The proof follows from information theory — you cannot losslessly compress arbitrary data into a fixed-size vector. A state of dimension 256 can hold at most 256 dimensions of information, regardless of how clever the compression is. If the task requires retrieving one specific fact from among thousands of stored facts, the compressed state literally does not have the capacity.

The KV cache is not a bug. It is a feature. The explicit storage of every past token — wasteful as it seems — is necessary for exact retrieval tasks. The question is not how to eliminate it, but how to use it sparingly: have attention layers only at the positions where the model needs to write to its database, and let SSM layers handle everything else.

Pure attention, meanwhile, cannot scale cheaply to 256K tokens. The quadratic cost and unbounded KV cache make it economically impractical at extreme context lengths. You pay for perfect recall at every layer, even when 90% of those layers only need compressed context. A 32-layer Transformer with 256K context maintains 32 separate KV caches, one per layer, each storing all 256K tokens. That is 32 × 256K separate key-value pairs. Most of those caches go largely unused — the model looks up specific facts in only a handful of layers — but you pay for all of them.

The answer is both. A brain with access to a database. The brain (SSM layers) handles the vast majority of processing cheaply. The database (attention layers) appears only at the critical moments where exact recall matters. This is not a compromise. It is an insight: most of computation does not need exact recall, and paying for it everywhere is waste.

The Architecture: Brain + Database

Hybrid models interleave SSM layers and attention layers at a fixed ratio. The SSM layers process the bulk of the sequence efficiently — they are the brain, compressing context, handling the 90% of tokens that need understanding but not exact recall. Periodically, an attention layer acts as a database checkpoint — the KV cache appears, tokens are filed into explicit storage, and the model gains precise retrieval of the 10% that matters for exact recall.

Think of it as a pipeline. Nine Mamba layers flow forward cheaply, compressing and contextualizing. Then one attention layer pauses, examines what the brain has accumulated, and writes the critical facts into its KV cache. The brain continues. Nine more cheap layers. Another checkpoint. The ratio determines how much database overhead you pay. At 7:1, only 12.5% of your layers carry the expensive KV cache. The other 87.5% are pure linear-time.

In March 2024, AI21 Labs built the first large-scale hybrid: Jamba. The architecture interleaves Mamba and Transformer layers at a 7:1 ratio — seven Mamba layers for every one attention layer. MoE (Mixture of Experts) layers appear every two blocks for capacity without proportional cost: 52B total parameters, only 12B active at inference. The context window stretches to 256K tokens.

The design philosophy is deliberate. Mamba layers handle the global context flow — the conveyor belt that processes the full sequence cheaply. Every eighth layer, an attention layer acts as a quality control checkpoint, examining the compressed state and adding precise retrieval capability. The 7:1 ratio means 87.5% of layers are linear-time.

Jamba matched or exceeded Transformer-only models of equivalent active parameter count at dramatically lower memory footprint. Jamba 1.5 scaled to 398B total / 94B active with 72 layers and grouped-query attention, achieving state-of-the-art on NVIDIA's RULER long-context benchmark.

IBM took the ratio further with Granite 4.0-H: nine Mamba-2 layers per one Transformer block. The logic: Mamba-2 layers handle global context propagation. Periodically, that compressed context passes through a Transformer block for precise local parsing via self-attention, then continues through the next Mamba-2 group. Over 70% RAM reduction for long-context inference versus conventional Transformers. Up to 8x faster token generation. The 8B hybrid exceeded the 8B Transformer on all twelve evaluated tasks.

NVIDIA's Nemotron-H pushed to a 12:1 ratio (92% SSM layers), achieving up to 3x faster throughput than LLaMA 3.1. Microsoft's Phi-4-mini reported up to 10x higher throughput and 2-3x lower latency with its hybrid approach. TII's Falcon-H1 uses a three-way ratio (SSM:attention:MLP) to balance efficiency and expressivity. NVIDIA's Hymba takes a different approach entirely: hybrid heads within the same layer, mixing SSM and attention channels instead of alternating layers.

The signal from every major lab is the same: the age of pure attention is ending. Not because attention was wrong, but because it was expensive for what 90% of layers need to do. The 10% that need exact recall still get it.

That translates directly into serving the same model on fewer GPUs, or serving more concurrent users on the same hardware. The Tri Dao Thread Completes

We can now see the full arc. One person's obsession with the GPU memory hierarchy changed two fields.

2022 — FlashAttention

Tri Dao's PhD work identified that attention's bottleneck was IO, not compute. Standard attention materializes the N×N matrix in HBM, reads it back for softmax, writes it again. FlashAttention tiled the computation into SRAM blocks. Never materialize the full matrix. Same exact result, 2-4x faster. This became the standard attention implementation everywhere. Part I of this series.

2023 — Mamba

One year later, Dao co-authored Mamba with Albert Gu. The selective scan's hardware-aware kernel uses the identical principle: load parameters to SRAM, compute the recurrence in SRAM, never materialize the expanded state in HBM. The insight was not "SSMs are better than attention." It was: the memory hierarchy is the real bottleneck, regardless of what you are computing.

2024 — Mamba-2 / SSD

The duality paper made the connection explicit. SSMs and attention are two algorithms for decomposing the same structured matrix. FlashAttention optimizes the quadratic decomposition. The selective scan optimizes the linear decomposition. Mamba-2's chunked algorithm literally uses both: quadratic within chunks, linear between.

2026 — Mamba-3

Complex-valued SSMs turn out to be equivalent to RoPE — a Transformer technique. MIMO uses matrix multiplication as its core primitive. The boundary between the two fields dissolves. They were always the same field, seen from different angles.

The Meta-Lesson

The fundamental constraints are not architectural — they are physical. GPU memory hierarchies, matrix multiplication units, IO bandwidth. Any architecture that respects these constraints can be made fast. The question was never "attention or SSM?" It was always "how do you arrange your computation to match your hardware?"

Consider the symmetry. In 2022, the ML community believed attention was the answer and the only question was how to make it scale. Tri Dao made it fast with FlashAttention. In 2023, a new community formed around SSMs as the replacement for attention. Tri Dao made them fast with Mamba's IO-aware kernel. In 2024, he proved the two were the same thing with the SSD framework. In 2026, Mamba-3 uses RoPE — a Transformer invention — to implement complex SSM dynamics, closing the loop.

The through-line is not a preference for one architecture or the other. It is a preference for respecting the hardware. And a proof that when you do, the architecture stops mattering. Attention, recurrence, convolution — they are all matrix operations executed on silicon that has specific memory hierarchies, specific compute units, specific bandwidth constraints. The architecture that wins is the one that fits its operations to those constraints most precisely.

Where It Goes From Here

The trend line is clear. Pure Transformers dominated 2017-2023 — attention was all you needed, until the KV cache and quadratic cost became crippling at scale. Pure SSMs (S4, Mamba) showed linear-time was possible but exposed the recall wall. Hybrids (2024-present) combine both, getting 80-90% of the efficiency gain while retaining recall. And the duality (Mamba-2, Mamba-3) suggests the endgame: architectures that flexibly switch between SSM and attention modes within the same mathematical framework, optimized per-layer for what that layer needs.

The bet from Goomba Lab (Gu's research group at Carnegie Mellon): on high-resolution data — raw bytes, audio waveforms, DNA base pairs — SSMs will dominate outright, because attention is a poor inductive bias for data without semantic units. You do not want to "attend" to individual ASCII values. On tokenized language, hybrids will dominate, because some tasks genuinely require exact recall. The ratio will be learned, not hand-tuned — each layer deciding whether it needs a brain or a database.

The most ambitious vision: a single model that dynamically adjusts its computation mode per-layer and per-sequence, in real time. Short prompts use mostly the quadratic (attention-like) decomposition — it is faster for small N because matmul hardware is so efficient for small matrices. Long contexts activate the linear (SSM) decomposition — when N exceeds the crossover point (somewhere around 4K-16K tokens depending on hardware), linear scaling wins decisively. Recall-heavy tasks route through attention checkpoints where KV caches are maintained. Compression-heavy tasks skip them entirely, saving the memory and compute. The architecture adapts to the workload, not the other way around.

We are not there yet. Current hybrids use fixed ratios determined at training time — the same ratio for every input, every task, every sequence length. But the duality says the math allows dynamic selection. And hardware is getting better at conditional computation — the same trend that enabled Mixture of Experts routing (Part V) could enable Mixture of Algorithms. Route easy tokens through SSM layers. Route hard tokens through attention. The ingredients are assembling.

What's clear is this: the era of "attention is all you need" is over. Not because attention was wrong, but because it was incomplete. Attention is one decomposition of a matrix that can also be decomposed as a recurrence. Sometimes the quadratic decomposition is faster. Sometimes the linear one is. Usually, the answer is a mix of both. The future is not pure anything. It is the right algorithm for each layer, each sequence, each token — chosen not by ideology but by the physics of the silicon underneath.

The Close

Five articles optimized the Transformer. Part I attacked the KV cache with MQA, GQA, MLA, and FlashAttention — the first encounter with Tri Dao's IO-awareness principle. Parts II through V compressed weights to fewer bits, pruned redundant connections, routed tokens through sparse experts, and generated multiple tokens in parallel through speculative decoding. Every article found speed by changing the constants — smaller caches, fewer bits, sparser experts, smarter scheduling. Every article left the exponent intact.

This one asked whether we need the Transformer at all.

The answer — for now — is partly. The future is not pure anything. It is hybrid: state spaces for most of the work, attention for the moments that require exact recall. The ratio will shift. Mamba-3 already blurs the boundary. Complex SSMs are RoPE. The chunked algorithm is simultaneously attention and recurrence. The two decompositions of the same matrix are converging back into one.

But the principle underneath everything — from FlashAttention to MLA to Mamba to MoE — is the same. Respect the memory hierarchy. Move less data. Do more with what you have.

That principle does not care whether you are computing a softmax or a scan, tiling an attention matrix or fusing a selective recurrence. It cares only that your computation stays close to the silicon that does the work and far from the memory bus that slows it down.

Tri Dao understood this before most. He applied it to attention and made it fast. He applied it to state spaces and made them competitive. He proved the two are dual. And the hybrid architectures now being built by AI21, IBM, NVIDIA, Microsoft, and TII all encode the same lesson: the model that wins is the one that matches its computation to the physics of the hardware it runs on.

The bottleneck was never the architecture. It was the distance between where your data lives and where your data is needed. That distance is measured in nanoseconds and joules, in SRAM bandwidth and HBM latency, in the gap between a register file and a memory controller. Every technique in this series — tiling, quantization, pruning, sparse routing, speculative decoding, selective scanning — is a strategy for closing that distance.

That has always been the efficiency problem. That has always been the answer.

The Resolution Hypothesis: Why Data Format Determines Architecture

The Goomba Lab research group has identified a pattern that may predict architecture choices going forward. On high-resolution data — raw bytes (UTF-8), audio samples, DNA base pairs — even when matching for data volume, SSMs consistently outperform Transformers. The hypothesis: at byte level, the data is too redundant for attention to be useful. You are "attending" to individual ASCII values. The inductive bias of compression (SSM) is far more appropriate than the inductive bias of retrieval (attention).

On BPE-tokenized text, each token carries enough semantic meaning to warrant explicit storage. The attention mechanism earns its quadratic cost because tokens are meaningful enough to retrieve individually. This suggests the optimal architecture depends not just on the task, but on the tokenizer: the granularity of your input representation determines whether a brain or a database serves you better.

As models increasingly process raw modalities — bytes, pixels, audio frames — the balance may shift further toward SSM-dominant architectures. Byte-level language models, multimodal models, and genomics models are the frontier where SSMs may ultimately displace attention entirely.
