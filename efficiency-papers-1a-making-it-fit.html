01 // The Memory Wall

Every token you generate means reading the entire KV cache. At Qwen 72B with 32K context, that is 10 GB of reads — for one word. Your GPU spends 95% of its time waiting for data, not computing. The compute cores can do 312 trillion operations per second, but they are fed through a 2 TB/s straw. The straw is the bottleneck.

And every token makes the cache bigger. The visualization below shows what that looks like as context grows.

Now watch the two phases of inference. Prefill processes your entire prompt at once — big matrix multiplies, GPU fully lit. Decode generates one token at a time — tiny vector operations, GPU mostly dark.

Prefill vs Decode — two universes of GPU utilization
The arithmetic gap

The GPU can multiply 16x faster than it can read. During decode, it reads everything and multiplies almost nothing. Arithmetic intensity during prefill: ~150 ops/byte. During decode: ~1 op/byte. The GPU is a sports car stuck in a parking lot.

02 // FlashAttention

You have seen the memory wall. Now look at where most of that memory goes. During attention, the model computes a score between every pair of tokens — an N×N matrix. At 8,192 tokens, that is 67 million entries. Standard attention writes this entire matrix to GPU main memory, reads it back for softmax, then writes it again. Four trips through the bottleneck for a single attention layer. Multiply by 80 layers and you see the problem.

In 2022, Tri Dao showed you could avoid materializing that matrix entirely — and get the exact same answer.

The left panel below shows standard attention materializing the full matrix in slow HBM. The right shows Flash processing tiles in fast SRAM. Drag the sequence length slider and watch quadratic memory blow up while Flash stays linear.

Imagine adding up a column of 1,000 numbers. The naive way: write all 1,000 on a whiteboard, then sum them. FlashAttention's way: keep a running total on a Post-it note, reading numbers one at a time. Same answer. The whiteboard is never needed.

The catch is that softmax needs the maximum of all values first. FlashAttention keeps a running maximum. When it finds a bigger number, it retroactively corrects everything with one multiplication. Like adjusting a grading curve mid-exam — one correction fixes all previous scores.

FlashAttention computes more total arithmetic than standard attention. It recomputes some values instead of storing them. But it is faster because memory trips — not arithmetic — are the bottleneck. Doing extra math is free when the GPU is waiting for data anyway.

This is the central insight of every optimization in this article: trade compute for memory access. The GPU has compute to spare. What it lacks is bandwidth.

Zero approximation

FlashAttention does not approximate anything. It computes the exact same answer, just without the memory waste. The principle never changed across three generations. The depth of application did.

03 // The Outlier Discovery

In 2022, Tim Dettmers tried to run transformers in INT8. Small models worked fine. At 6.7 billion parameters, something broke. Every layer suddenly coordinated on the same 6 dimensions for extreme values — 100x larger than normal. These are not noise. They are how the model steers attention. Clip them, and it forgets how to focus.

The visualization below shows a weight matrix. Most values are small (blue). But a few columns are bright red — outliers. Toggle the controls to see what happens when you clip them versus handling them intelligently.

Emergent Outliers — the phase transition at 6.7B parameters
Quality: 100%

In a typical transformer layer, most activation values hover between -1 and +1. But 6-7 channels carry values of 50-100. These channels are the model's steering system — they control which tokens get attended to and how strongly. They are not bugs. They are the most important features the model learned.

Below 6.7B parameters, outliers appear randomly and scatter across different channels each layer. Above that threshold, something snaps: the same columns light up in every layer. The model spontaneously develops a privileged coordinate system. Quantize those coordinates and the whole model breaks.

LLM.int8() is elegant: do not try to fit outliers into the INT8 grid. Just do not quantize them. Keep the 0.1% of values that are outliers in full FP16 precision. Quantize everything else to INT8. The model uses half the memory and loses nothing.

The implementation is a matrix decomposition. Split every hidden state into two paths: the 6 outlier columns go through an FP16 matmul, the remaining 4,090 columns go through INT8. Sum the results. Two matmuls instead of one, but 99.9% of the work is in INT8.

The phase transition

Dettmers did not just solve a quantization problem. He discovered that large transformers spontaneously develop a privileged coordinate system — 6 dimensions out of thousands that control everything. This was the first evidence that scale changes the internal structure of the model, not just its accuracy.

04 // The Weight Surgeons

Three groups independently asked the same question: which weights can you round without killing the model? They found three different answers. GPTQ sweeps column by column, redistributing error via the Hessian. SmoothQuant transfers difficulty from spiky activations to smooth weights. AWQ protects the 1% of weights that activations actually use.

Click each method below to see how it transforms the same weight matrix. Watch the quality readout.

Three Scalpels — four methods, one weight matrix
Perplexity: 6.57 (FP16 baseline: 6.57)

Which weights, if rounded, cause the most damage? The Hessian (second derivative of loss) tells you. GPTQ quantizes column by column, and each column's rounding error gets redistributed to the columns that have not been quantized yet. Later columns absorb earlier mistakes.

The sweep moves left to right through the weight matrix. By the time it reaches the last column, accumulated corrections have spread the error thin across thousands of parameters. A 175B model quantizes in 4 GPU hours. The result: 3-4 bit weights with perplexity within 0.05 of the original.

Activations are spiky. Weights are smooth. SmoothQuant transfers the difficulty: divide activations by a per-channel scale, multiply weights by the same scale. The math is identical. But now both fit cleanly into INT8.

Like pouring water from a tall narrow glass into a wide flat one. Same volume, different shape. The tall glass (activations with outliers) overflows the INT8 range. The flat glass (smoothed activations) fits perfectly. One offline calibration pass finds the scales. Inference runs entirely in INT8.

The experiment that changed everything: protect the top 1% of weights selected by weight magnitude → perplexity 22.37 (terrible). Protect the top 1% selected by activation magnitude → perplexity 11.36 (near-perfect). The weights that matter are not the biggest. They are the ones the model actually uses.

AWQ scales up the important channels before quantization so they get more of the INT4 grid. No mixed precision needed, no special kernels for outlier paths. Just a per-channel multiply that makes the right weights louder before the rounding happens.

The shared insight

Three groups, three methods, one lesson: the weights that look important are not the weights that are important. What the model uses matters more than what the model stores.

05 // The GGML Revolution

GPTQ, SmoothQuant, and AWQ are research tools — they prove what is possible. But running a quantized model on your laptop requires something else entirely: a runtime that understands block quantization at the hardware level, can be compiled on any platform, and does not need a GPU at all. That is what one person built.

March 2023. LLaMA leaks. Seven days later, Georgi Gerganov — a Bulgarian medical physicist who called himself "a non-AI-believer" — has it running on a MacBook. Quantized to 4 bits. No GPU. His C library now powers Ollama, LM Studio, GPT4All, and every local AI tool you have heard of.

His innovation: block quantization. Instead of one scale for the whole tensor, give every 32 weights their own scale. Then quantize the scales themselves. Then use calibration data to give important weights more bits. Click through the levels below.

The constraint-driven thesis

Not having access to GPU clusters drove more innovation than having them. Google, Meta, and OpenAI had unlimited compute but built inference systems that required unlimited compute. Gerganov had a MacBook and built something that ran on everything. The constraint was the advantage.

06 // The Radical Frontier

What if every weight was -1, 0, or +1? No multiplication — just addition. Microsoft's BitNet proved a 2B ternary model uses 0.4 GB and runs at human reading speed on CPU. Six times less memory, twelve times less energy, within 2% of full-precision quality.

And the most important lesson in this article: AWQ without the right kernel runs slower than no quantization at all. The Marlin kernel makes it 10.9x faster. Math without engineering is just theory. Watch:

The Kernel Gap — same algorithm, different execution
The kernel lesson

The algorithm is not the bottleneck. The execution is. AWQ's math compresses the model beautifully. But with the default kernel, inference is 7x slower than FP16. Marlin transforms the same model from 0.15x to 1.61x FP16 speed. A 10.9x improvement from the CUDA kernel alone. Mathematical elegance is worthless without the right execution engine.

Your gaming PC can run a 72B model. Q4_K_M in GGUF format, running through llama.cpp, loaded in Ollama. No internet, no API costs, no data leaving your machine. Part I-B asks: what happens when ten thousand people try to do that at the same time?
